imapvault

Every state of your mailbox, kept safe.

Open-source IMAP backup with point-in-time snapshots. imapvault keeps deleted mail for a grace period, notices when a mass deletion happens, and restores any snapshot, folder or message.

For the bad day

Someone gets into your account, deletes everything and empties the trash. A mirror copies that deletion. imapvault does not: the next run notices, raises an alert, pins the last good snapshot and tells you: backup exits with code 3, and run posts to a URL you set, such as an ntfy topic. imapvault restore puts the mail back.

How it works

  1. backup reads the mailbox in one read-only session and stores each distinct message once, compressed and, if you want, encrypted with age.
  2. Every run is a snapshot: a cheap index of what was where, with flags. Moves and renames cost no extra storage.
  3. The guard compares each run with the last one. Too many deletions, or a vanished folder, flags the snapshot, pins the previous one and runs your alert command or posts to a webhook.
  4. run does all of this on a schedule: it backs up every hour, applies the retention policy daily, retries failures, keeps going after an alert and tells you if backups stop working. It prunes only if you ask.
  5. forget and prune apply a retention policy. Mail deleted from the server stays restorable for 180 days by default, and pins and open alerts always win.
  6. restore shows exactly what it would add, then waits for a plan token you copy from the preview.
# keep it going: back up hourly, tidy daily, alert if something is wrong
imapvault --account personal run

# or one backup at a time, from cron or a systemd timer
imapvault --account personal backup

# what changed between two snapshots
imapvault --account personal diff latest~1 latest

# undo the hack: preview first, then approve with the token it prints
imapvault --account personal restore --deleted-since 7d --in-place

Careful with your mail

  • Backup is read-only on your server: EXAMINE and BODY.PEEK[], and a test fails the build on any write command.
  • Restore only creates folders and appends messages. It never deletes, moves or re-flags anything, and needs allow_append = true in the target account's config plus an approved plan token.
  • Backup never needs your private key. A cron job or NAS with only the public key can back up, prune and verify, and cannot read a single message.
  • Only prune removes data from the repository, and it honours pins, the grace period and unacknowledged alerts. run never prunes unless you pass --prune-every.
  • It never logs message bodies, subjects or credentials.

Install

One static binary for Linux and macOS, on amd64 and arm64. The script checks the download against the published checksums before it installs anything, and puts imapvault in ~/.local/bin.

curl -fsSL https://imapvault.sh/install.sh | sh

Or brew install michele/imapvault/imapvault, or the container image ghcr.io/michele/imapvault. Prefer to read the script first? install.sh is short. You can also take an archive from the releases page. The macOS binaries are not signed, so Gatekeeper refuses the first run: xattr -d com.apple.quarantine imapvault. To keep it running, use imapvault run. The Docker guide has a Compose file that starts it with docker compose up -d, with a NAS in mind; for cron or systemd timers see the scheduling notes.

Status

This is a brand new project and I am still working on it, so expect rough edges. It has been tested with Fastmail and Gmail, and it should work with most IMAP providers. Restore has only been run against a test server, so try it on a throwaway account before you point it at a mailbox you care about.

Use it at your own risk. It is released under the MIT licence with no warranty, and a backup you have never restored is a hope, not a backup.

What is and is not verified is listed milestone by milestone in the plan.
